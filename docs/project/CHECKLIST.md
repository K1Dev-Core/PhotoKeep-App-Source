# เช็กลิสต์ส่งงาน PhotoKeep

เกณฑ์จากภาพที่ให้มาแบ่งเป็น **ความคืบหน้า 3 คะแนน + เทคนิคตามโจทย์ 12 คะแนน + ความยาก/ความเข้าใจ 5 คะแนน = 20 คะแนน** ตารางนี้เป็นสถานะของงานและหลักฐานสำหรับสาธิต ไม่ใช่คะแนนที่รับประกันแทนอาจารย์ ตรวจสถานะล่าสุดเมื่อ 24 ต.ค. 2569

สรุปตอนนี้: **build ผ่านและมีหลักฐานวิเคราะห์ครบ 1,000 รูป แต่ยังไม่ผ่านการตรวจรับครบทุกหัวข้อ** จุดที่ยังต้องทดสอบคือเปิดแอปบน Windows จริง, สำรองข้ามไดรฟ์จริง และประเมินความแม่นของผลค้นหาหลายชุด

## เกณฑ์ในโจทย์

| หัวข้อ | คะแนน | สถานะ | จุดสาธิตและหลักฐาน |
| --- | ---: | --- | --- |
| Wails + Nuxt บน Windows/macOS | 1 | ⚠️ macOS เปิดได้, Windows cross-build ผ่านแต่ยังไม่เปิดทดสอบจริง | แอปกำลังรันบน macOS; สร้าง Windows x64 PE ด้วย MinGW ได้ แต่ยังต้องเปิดบน Windows ที่มี WebView2 |
| SQLite + GORM | 2 | ✅ ผ่าน | `internal/photokeep/service.go` เปิดฐานข้อมูลด้วย GORM/SQLite; ฐานข้อมูลที่ใช้งานมีรูป 1,000 รายการ |
| Backup ต่อจาก midterm | 2 | ⚠️ ไฟล์สำรองครบ แต่ยังไม่พิสูจน์ข้ามไดรฟ์ | ตรวจพบไฟล์ต้นฉบับและสำเนา 1,000/1,000 ไฟล์ แต่ทั้งคู่ยังอยู่ volume เดียวกัน; ยังไม่ตรงเกณฑ์ทดสอบจาก drive จริง |

**ข้อสังเกตเรื่อง midterm:** โปรแกรมเดิมเป็น CLI ที่มีคำสั่งจัดการไฟล์เพิ่มเติม เช่น `/list`, `/check`, `/delete`, `/clean` แอป Final นี้นำความสามารถแกนหลักของการตั้งค่าโฟลเดอร์และสำรองไฟล์มาต่อยอดเป็นคลังรูป โดยไม่ได้ย้ายคำสั่งจัดการไฟล์ทั้งหมดขึ้น UI เพราะงาน Final ระบุระบบสำรองรูปและค้นหาเป็นเป้าหมายหลัก หากอาจารย์ตีความ “เทียบเท่าข้อสอบกลางภาค” ว่าต้องมีทุกคำสั่งเดิม ควรถามยืนยันก่อนวันสาธิต

## ลำดับสาธิต 5 นาที

1. เปิด **ตั้งค่า** และเลือกโฟลเดอร์ตัวอย่างเป็นต้นทางกับโฟลเดอร์ว่างเป็นปลายทาง
2. กด **สำรองรูป** แล้วแสดงรูปหลายรูปในแกลเลอรีและไฟล์สำเนาที่ปลายทาง
3. เปิดรูปหนึ่งรูป แสดงขนาด/วันที่ แล้วเพิ่มคำอธิบายและแท็ก
4. ค้นคำในคำอธิบาย จากนั้นล้างคำค้นหาและกดแท็กใน Tag Cloud
5. กดสำรองอีกครั้งเพื่อแสดงจำนวนรูปที่ข้าม และยืนยันต้นฉบับยังอยู่

## รายการที่ยังต้องทำก่อนสรุปว่าผ่าน

1. เปิดไฟล์ Windows x64 บน Windows จริงและเดิน flow ตั้งค่า → สำรอง → เปิดรูป → ค้นหา
2. เลือกต้นทางจากไดรฟ์จริงและปลายทางคนละ volume; สำรองชุดทดสอบและยืนยันไฟล์ครบ ต้นฉบับยังอยู่ และ UI ไม่ค้าง
3. สุ่มตรวจ caption/tag จากงาน 1,000 รูป และทดสอบคำค้นหลายหมวดทั้งไทย/อังกฤษ พร้อมบันทึกเวลาและภาพที่ไม่เกี่ยว
4. หัวข้อการนำเสนอและการมีส่วนร่วมของสมาชิกต้องยืนยันจากการสาธิต/หลักฐานทีม ไม่สามารถตัดสินจาก source code อย่างเดียว
