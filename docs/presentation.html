05

สำรองภาพ — ขั้นตอนและการป้องกันข้อมูล

สำรวจไฟล์ → กรองไฟล์ที่รองรับ → คัดลอกแบบ atomic → ตรวจ hash → บันทึกข้อมูล → สร้าง thumbnail

  1. 01
    ตรวจ source/destinationต้องเป็นโฟลเดอร์ที่มีอยู่และห้ามซ้อนกัน เพื่อป้องกันวงจรคัดลอกหรือลบผิดที่
  2. 02
    สแกน recursively และตัดไฟล์ซ่อนรองรับ jpg/jpeg/png/gif/webp/bmp/tif/tiff; ข้ามชื่อขึ้นต้นด้วยจุด เช่น .DS_Store
  3. 03
    คัดลอกด้วย worker poolสูงสุด 4 worker ตาม GOMAXPROCS; เขียน temp file ก่อน rename และตรวจ byte count
  4. 04
    ตรวจ SHA-256 และรายการเดิมถ้า hash ตรงกันจะข้าม; ถ้าชื่อซ้ำแต่เนื้อหาไม่ตรงจะตั้งชื่อใหม่ต่อท้าย (1), (2), …
  5. 05
    เก็บต้นฉบับหรือย้ายค่าเริ่มต้น keep original = true; ถ้าปิด ระบบบันทึกสถานะย้ายก่อนลบต้นฉบับ
  6. 06
    อัปเดต progress และเริ่มงานถัดไปเมื่อ backup ผ่าน ระบบจัดคิว AI analysis และเริ่มทำ embedding index

06

งานวิเคราะห์ภาพด้วย AI

เก็บงานเป็น job ใน SQLite; แสดงสถานะรายภาพและให้ retry เฉพาะรายการที่ต้องทำต่อ

✦

ลำดับทำงาน

  • เรียก GET /health ก่อนเริ่ม job
  • บันทึก job และตั้งรูปเป็น pending
  • อ่าน concurrency จาก health ของ Gateway
  • ส่งภาพแต่ละใบด้วย multipart field file
  • บันทึก caption, tags, model และสถานะลง SQLite
  • 429 จะ defer คิว; error ชั่วคราว retry ตาม Retry-After/backoff
⇲

ปรับรูปก่อนส่ง

  • ขนาดต้นฉบับก่อนเตรียมได้สูงสุด 100 MB
  • ย่อด้านยาวสุดไม่เกิน 768 px
  • เข้ารหัส JPEG quality 82
  • ไฟล์ payload สูงสุด 12 MB
  • ไฟล์ชั่วคราวถูกลบเมื่อคำขอจบ
app.go · worker count ปัจจุบันอ่านจาก Gateway health
concurrency, concurrencyErr := client.Concurrency(concurrencyCtx)
concurrencyCancel()
if concurrencyErr != nil {
    concurrency = 1
}
workers := min(max(1, concurrency), len(inputs))
for range workers {
    go func() {
        for input := range work {
            result, err := client.Analyze(ctx, input.Path)
            if ctx.Err() != nil {
                continue
            }
            if err == nil {
                err = photokeep.ValidateThaiAnalysis(result)
            }
            results <- outcome{input: input, result: result, err: err}
        }
    }()
}
ส่วนคำนวณจำนวน worker ตรงกับ source; body ใน loop ย่อให้เห็น flow เท่านั้น
ผลต่อเวลา: เพิ่ม worker ในแอปเกินค่า concurrency ของ Gateway ไม่ได้เพิ่มจำนวน inference จริง แต่อาจสร้างคิว HTTP และแย่ง SQLite write lock จึงต้องปรับและ benchmark เพดานที่ Gateway ด้วย
เรื่อง cache ที่ควรพูดให้ถูก: ตอนนี้ SHA-256 ใช้ตรวจรูปซ้ำในงานสำรอง ยังไม่มี cache ผลวิเคราะห์ AI ที่ข้ามการเรียก Gateway ตาม image hash; ถ้าจะเพิ่ม ต้องผูก cache key กับ hash, provider/model และ prompt version และเก็บเฉพาะผลที่ validation ผ่าน

08

ระบบค้นหา — ข้อความ + ความหมาย

ค้นหาในเครื่องเป็นหลัก; เรียก embedding API เฉพาะเวกเตอร์ของข้อความค้นและตอนสร้างดัชนีภาพ

1 · รับ queryคำค้น / tag / offset / limit
2 · lexicalFTS5 + Thai tokenizer จัดอันดับข้อความ
3 · text vectorใช้ cache ใน memory; timeout 10s
4 · cosineเทียบกับ image vectors ใน SQLite
5 · fuseรวม lexical + semantic แล้วแบ่งหน้า

Lexical search

SQLite FTS5 trigram หา filename/caption/tags; ตัวตัดคำไทยสร้าง token; ให้คะแนน tag มากกว่าชื่อไฟล์และคำอธิบาย; คำตรงทั้งวลีได้คะแนนเพิ่ม

Semantic search

สร้างเวกเตอร์ query จาก embedding service แล้วคำนวณ cosine similarity ในเครื่อง เฉพาะรูปที่มี embedding model เดียวกับ query; ใช้ threshold และ margin จำกัดผลรบกวน

Fallback

ถ้ายังไม่มี image embeddings, service ไม่พร้อม หรือ query embedding ล้มเหลว จะคืน lexical results แทน; ผลค้นยังใช้งานได้โดยไม่รอ AI เกิน timeout

ดัชนีภาพ

หลังสำรองภาพ ระบบอ่าน pending embedding; ย่อภาพก่อนส่ง; บันทึก vector เป็น binary float32 พร้อมชื่อโมเดลใน row ของ photo

internal/photokeep/embeddings.go · cosine score ในเครื่อง
func cosineSimilarity(left, right []float32) float64 {
    if len(left) == 0 || len(left) != len(right) {
        return -1
    }
    var dot, leftNorm, rightNorm float64
    for i := range left {
        a, b := float64(left[i]), float64(right[i])
        dot += a * b
        leftNorm += a * a
        rightNorm += b * b
    }
    if leftNorm == 0 || rightNorm == 0 {
        return -1
    }
    return dot / math.Sqrt(leftNorm*rightNorm)
}
ค้น semantic ไม่ได้ส่งภาพทุกใบไปให้ AI ใหม่; ใช้เวกเตอร์ที่บันทึกไว้เทียบ cosine
ข้อควรพูดตรง ๆ: คุณภาพ semantic ขึ้นกับโมเดล embedding และภาษาที่โมเดลเข้าใจ; เมื่อเปลี่ยน embedding model ต้องสร้าง vector ของรูปใหม่ให้เป็น model เดียวกัน

สาธิต 6–8 นาที

  • นาที 1: ตั้ง source / destination และอธิบายการเก็บต้นฉบับ
  • นาที 2: สำรองรูป; แสดง progress, skip ซ้ำ และไฟล์ที่คัดลอก
  • นาที 3: เปิด Gallery, เลื่อน, thumbnail และรายละเอียดภาพ
  • นาที 4: แก้ caption/tag แล้วค้นด้วยคำไทย
  • นาที 5: เริ่ม AI job, แสดง status และ pause/resume/retry
  • นาที 6: อธิบาย Gateway แยกคีย์และ provider
  • นาที 7–8: semantic search และนำเข้า theme

ก่อนวันนำเสนอ

  • เตรียมโฟลเดอร์ demo สำเนา ไม่ใช้รูปส่วนตัว
  • ตรวจ `.env` endpoint กับ `/health` ของ Gateway
  • ยืนยัน model + concurrency จาก health ล่าสุด
  • รัน `go test ./...`, `npm run typecheck`, `npm run generate`
  • ตรวจว่า embedding index ครบก่อนสาธิต semantic
  • เตรียมภาพ/คำค้นสำรองกรณีเครือข่ายหรือ AI ใช้ไม่ได้
  • ไม่แสดง API keys หรือไฟล์ `gateway.env` บนจอ

พูดถึงความเร็วอย่างไร

ตัวเลขที่เห็นก่อนหน้า 369/1,000 ใน 2 นาที 49 วินาที คิดเป็นราว 131 ภาพ/นาที หรือประมาณ 7 นาที 38 วินาทีต่อ 1,000 ภาพ หากอัตราคงที่ ตัวเลขนี้เป็นการคำนวณจาก progress ณ ตอนนั้น ไม่ใช่ benchmark ครบ 1,000 ภาพ เป้าหมาย 2–3 นาทีต้องได้ 5.6–8.3 ภาพ/วินาที และต้องทดสอบกับ Gateway, provider quota และฐานข้อมูลจริงก่อนกล่าวว่าผ่าน
ความต่างของ concurrency: แอปใช้จำนวนที่อ่านจาก Gateway health; หากตั้ง worker ฝั่งแอปมากกว่า Gateway จะได้เพียงคำขอรอ ไม่ได้เพิ่มจำนวน inference ที่กำลังทำจริง ควร benchmark เพิ่มทีละระดับและดู 429, p50/p95 latency และ SQLite write delay
